# 评估与实验规范

> 状态：MVP 质量判定标准。任何“AI变好”结论必须由本规范支持。

## 1. 固定对照组

每周永久保存：

1. `rule_baseline`：V9.0纯规则目标且最多5只，候选不足时保留实际数量。
2. `ai_adjusted`：AI有限调整后的同容量集合。
3. `published`：人工确认后正式集合，记录实际数量与不足原因。

核心增益：

- AI增益 = `ai_adjusted - rule_baseline`。
- 人工增益 = `published - ai_adjusted`。

不得只评价最终发布版后声称AI有效。

集合容量必须随版本一并保存。正式目标和上限为 5 只，硬约束后可发布 1～5 只；零只时记录停止发布而不计算伪组合收益。不同容量的触达数与触达率必须同时报告，不能把较小集合天然形成的差异直接归因为策略增益。

## 2. 传统指标

- 目标触达率：实际发布集合中周内最高涨幅达到各自目标的比例，分母必须同时报告。
- 核心10%触达率：周内最高涨幅至少10%的比例。
- 平均与中位周内最高涨幅。
- 周终平均与中位收盘涨幅。
- 平均、最差和中位最大回撤。
- 剔除最强单一标的后的组合指标。

## 3. 可执行与相对指标

- 当周首个交易日开盘是否停牌、涨停或明显不可成交。
- 研究基准与模拟入口分开报告；开盘后30分钟VWAP仅在分钟数据通过可重放性验证时启用，否则明确标记不可用。
- 计入可配置滑点与费用后的目标触达。
- 触达目标前最大回撤和触达用时。
- 相对沪深300及所属行业的周度超额。
- 与同领域随机/分层抽样同容量集合的参考分布。

每日简报不作为换股、盘中择时或周行情判断来源。应评价生成成功率、时点合规率、当日行情完整度和 AI 摘要引用合规率；周度表现及风险只在周终复盘评价。

## 4. 多目标判定顺序

约 10% 周内最高涨幅触达是核心业务目标，但不是唯一优化目标。实验和周终复盘按以下顺序判定，不允许用下层指标改善抵消上层违规：

1. 数据时点、硬约束、组合约束和发布权限零违规。
2. 开盘成交可达性、关键数据完整度和结果可重放。
3. `touch_10_rate`、触达数量及其置信区间/样本规模。
4. 触达前回撤、最大回撤和触达用时。
5. 周终收盘留存、相对沪深300及行业超额。
6. 剔除最强标的后的表现和单一锚点贡献占比。
7. 概率校准、稳定性、复杂度与运行成本。

正式入选的每只股票必须在决策时具备约 10% 研究情景；“具备情景”与“事后触达”分开记录，不得把情景目标描述为收益保证。

## 历史时点回放实现口径

- 同时保存“模拟信息截止时间”和“实际抓取时间”，严禁把事后抓取时间倒填为历史时间。
- 周初行情只允许到前一交易日收盘；每日简报只允许到该交易日收盘；周终评价只允许到最后交易日收盘。
- 分类和其他事实还必须满足 `published_at <= 模拟截止日期`。
- 事后前复权序列无法证明与历史当日版本完全一致，标记 `QFQ_VINTAGE_NOT_CAPTURED_AT_ORIGINAL_TIME`，仅用于研究回放。
- 2026-08-03 周真实验收的数据截止日依次为 07-31、08-03、08-04、08-05、08-06、08-07，周终截止 08-07。

传统触达与可执行指标不能互相替代。

## 5. 概率校准

对 `touch_probability` 和 `close_positive_probability` 计算：

- Brier Score。
- 分箱命中率（样本不足时不作强结论）。
- 预测概率与真实频率偏差。
- 按市场状态、领域和模型版本拆分的过度自信程度。

少量周样本只展示累计事实，不做显著性夸大。

## 6. 历史实验

- 使用walk-forward：每个决策周只允许读取此前数据和此前已完成的复盘。
- 训练/调参区间与最终验证区间分离；同一区间不能既选参数又宣称验证成功。
- 股票池、ST、停牌、上市日期和行业分类都使用当时状态。
- 历史Markdown可作为结果核对材料，不能替代可复现的数据快照。
- 每个实验记录规则、特征、模型、提示词、数据版本、运行时间、Token/成本和代码版本。
- 同一自然周存在并行规则版本时，以“周 + 实验臂”作为回放唯一键，不把新旧规则文件互相覆盖。
- 周度组合结果保持原子性：某份发布名单只要有一个标的结果缺失、漂移或冲突，该周该实验臂就不得用剩余标的计算组合指标，避免幸存者偏差。发布不足5只的周按实际发布数量判断完整性。
- 单源复算一致的历史结果只能用于研究性回放；正式验证必须满足已确认的数据质量和快照可复现要求。

每次 walk-forward 必须冻结折叠契约：训练/归因窗口、参数选择窗口、最终验证窗口、最小样本、缺失周处理、基准版本和随机种子。参数只能在选择窗口确定，验证窗口完成前不得根据其结果回调参数；每个折叠保存输入快照、候选全集、逐项指标和组合原子性状态。

实验报告必须同时给出各折结果和聚合结果，并按市场状态、领域、集合容量拆分。若改进只出现在单一状态、单一领域、单只股票或少数容量更小的周，必须明确标记，不能用一个总平均数掩盖。

## 7. 实时影子实验

实验版与正式版使用同一冻结快照并行运行，但不影响正式发布。至少记录名单差异、预测概率、周终结果、数据与模型故障。

单周胜出不构成升级依据；默认至少观察5个完整周，涉及自动发布时使用更严格门槛。

## 8. 优化升级门槛

规则或AI策略升级至少满足：

- 无未来数据泄漏和硬约束违规。
- 验证区间核心指标不劣于正式基线。
- 平均高点、收盘留存、回撤或概率校准中至少一项有明确改善，且不存在不可接受的另一项退化。
- 改善不能主要由单只锚点贡献。
- 实时影子结果与历史结论方向一致。
- 用户批准并指定回退版本。

升级依据必须绑定唯一实验提案及完整状态历史。`replay_passed` 仅表示有资格进入影子运行，`shadow_running` 不具有发布权限；只有历史与影子方向一致、所有上层门禁通过并由用户批准后，才能创建新的正式版本。激活后若出现硬约束违规、时点泄漏、不可重放或预设失效条件，应停止该版本并按指定版本回滚。

## 9. 自动发布门槛

从人工确认切换为自动发布前，建议同时满足：

- 至少12个完整交易周稳定运行。
- 数据任务成功率不低于99%。
- 零未来数据泄漏和严重硬约束事件。
- AI结构化输出与审计合规率接近100%。
- 最近阶段人工修改名单比例不高于10%。
- AI版本滚动结果不劣于纯规则版本，且未持续扩大回撤。
- 每个正式结果可完整重放。
- 数据或AI异常时能停止自动发布并转人工。

建议模式依次为：人工确认 → 自动生成但超时不发布 → 自动发布且异常转人工。

## 10. 测试基准

开发时必须建立固定样例覆盖：正常周、单一锚点周、系统退潮周、广度恢复周、恢复失败周、休市周、候选 5/4/3/2/1/0 只、停牌/涨停不可达、复权事件、数据源冲突、AI降级、DSL 未知特征/越界参数/未来标签、回放分折隔离、影子无发布权限、审批与回滚。
