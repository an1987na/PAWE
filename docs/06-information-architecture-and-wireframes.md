# 信息架构与低保真线框

> 状态：MVP 交互基线。原则：结果优先、证据按需、过程默认隐藏、决策始终可审计。

## 1. 信息层级

- L0 结果：首页可直接决策的信息。
- L1 说明：核心证据、风险、失效条件和名单变化。
- L2 研究：行情、行业、财务、公告、资金、新闻与历史案例。
- L3 审计：快照、规则触发、工具调用、结构化AI响应、版本和人工记录。

首页不得直接展示L2/L3长内容。

10. 设置

当前 Web 将“周终复盘”收敛为顶部“历史数据”入口：列表只展示边界清晰的周记录，点击后在周级弹框显示该周完整名单、日报和复盘，标的详情继续使用弹窗按需查看。

当前 Web 另设一级“AI 工作台”：用户可关联本人 OpenAI API 凭据并查看连接状态；工作台集中放置周初名单分析、周终复盘解读、错误归因和规则迭代。规则迭代只接受人工确认的归因并输出隔离实验提案，周初分析和规则迭代仍受管理员权限保护。

决策管理采用单屏总览：决策版本标题行右侧直接放置同色同尺寸的“周初名单 / 每日简报 / 周终复盘”三个任务入口，不再单设人工产出控制卡片。正文为左右结构，左侧正式发布版、右侧默认收起的任务进度与审计；等待发布和中间规则版本不展示。

个股研究从股票实体进入，不必占用一级导航。

主页不得展示硬编码演示标的。登录后只读取当前自然周处于 `published` 且激活的正式决策集；没有正式发布时展示明确空状态，并说明历史迁移结果、候选或演示数据不会自动成为正式名单。

## 3. 驾驶舱

```text
┌ PAWE · 2026-W32 ─────── 市场：退潮后轮动  置信度：中  待确认 ┐
│ 本周标的（目标且最多5只；当前实际数量）                       │
│ 代码    目标情景  概率  核心理由                  主要风险   │
│ 002472  10%-12%   43%   机器人传动成组转强        成交待确认 │
│ ...                                                          │
├──────────────────────────────────────────────────────────────┤
│ 领域热度        上周结果        AI增益        系统状态        │
│ 机器人 ↑        2/5触达         +1席改善       数据正常        │
└──────────────────────────────────────────────────────────────┘
```

默认个股行只显示：目标情景、触达概率、一句话理由、一句话风险、置信度。

交互按需展开：点击个股查看冻结规则理由、评分构成和主要风险；点击市场状态查看六类状态及当前状态；点击组合置信度查看三级口径；决策版本只保留简短编号，点击后解释其在数据、规则、审批和发布审计中的定位作用。

首页采用与历史数据、决策管理相同的内容宽度、头部字号、导航按钮和标准正文排版：左侧完整展示实际发布的 1～5 支名单，观察名单下方提供统一的每日简报入口，右侧展示市场状态、组合置信度、版本等周度摘要。零只时显示停止发布原因，不渲染空名单卡片。不得再为首页单独使用 10px/11px 压缩字号。每周标的与我的自选复用同一弹框结构，在弹框顶部按交易日倒序选择指定日报；弹窗支持 ESC、关闭按钮及点击外部关闭。以 `1280×720` 为最低桌面验收视口时，已登录主页应尽量减少滚动，并完整保留最多 5 支名单、日报入口和四项组合状态；不得通过省略号或裁切换取紧凑。历史周结果不再占用首页，完整的新增证据、失效条件与历史版本进入独立页面。

右侧周度摘要底部提供紧凑的“我的自选 X/5”入口；其下独立提供“每日简报”和“每周复盘”两个个人入口。自选管理弹窗内按代码或名称搜索沪深 A 股、增删本人自选并显示生效交易日。系统日报与历史数据只展示公共决策及其回溯产出，个人自选日报和复盘只在“我的自选”区域展示，避免把个人跟踪结果误认为规则推荐。

## 4. AI决策确认

```text

股票A                股票A               [等待确认]
股票B  ──换出──>     股票F  +6           [接受AI版]
股票C                股票C               [修改并说明]

变化摘要：AI建议换入1只；组合仍满足全部硬约束。
[查看3条证据] [查看风险] [查看完整审计]
```

用户可以接受AI版、恢复规则版或修改名单；修改必须选择/填写原因。危险或不可逆操作才二次确认。

## 5. 候选中心

使用紧凑表格和筛选器，默认列：代码、名称、领域、规则分、AI调整、最终分、角色、状态、主要落选原因。科创参考和跨领域探索单独标签，不混入正式名单造成误解。

## 6. 每日简报

主页在本周研究区顶部并列提供“本周观察名单 / 每日简报 / 本周复盘”三个入口，点击后在同一区域下方切换内容；主页每日简报在内容区按交易日选择，并以紧凑行情行集中展示名称、代码、当日涨跌、相对量能和消息状态，避免五只标的重复大卡片造成不必要滚动；我的自选继续使用独立弹框并保持相同日报事实口径。日报只陈述所选交易日的当日收盘涨跌、相对前5日均量和当日消息证据，不展示周内最高、周内收盘进度、目标距离或周度风险状态；这些周度事实只在周终复盘形成。公告/新闻变化只允许基于已接入、带发布时间且不晚于简报生成时点的可追溯证据；没有证据时明确显示“暂无已验证消息证据”，不得由模型补写。不得出现换股、止盈或止损按钮。

## 7. 周终复盘

首屏只展示：三版本触达率、平均/中位高点、收盘留存、最大回撤、AI换入增益和本周主要错误。逐股结果、失败周反查和完整归因按需展开。

交互实现为“历史数据 → 周记录列表 → 周级归档弹框 → 周度决策版本/每日日报 → 标的详情”。主列表不原地展开，避免相邻交易周视觉边界混淆；周级弹框内，周度标的可点击查看入口、收益、回撤、基准超额、行业超额和目标触达详情，每日日报继续按交易日收敛并区分正式发布与历史回放来源。弹框支持 ESC、关闭按钮及点击弹框外部关闭。

## 8. 文案与状态

- 市场摘要建议不超过150字；个股理由不超过80字；主要风险不超过60字。
- 最多默认展示3条证据和2条风险。
- 必须有：加载、无数据、降级、冲突、低置信度、候选稀缺、待审批、已发布、任务失败状态。
- 颜色不作为唯一信息；数字同时带文本状态或图标说明。

## 9. 实验记录与系统健康

实验记录默认展示提案标题、基线版本、变更摘要、当前状态、历史回放结论、影子周数和待办动作。展开后按“假设与 DSL → 静态校验 → walk-forward 各折 → 影子对照 → 人工审批 → 激活/回滚”展示，规则差异必须翻译为可读参数变化；禁止提供跳过回放或直接激活的快捷操作。

实验页面只展示模型给出的结构化假设、证据和验证结果，不展示内部推理。`replay_rejected`、`shadow_failed` 和回滚必须直接显示失败门禁、受影响指标和原因；指标同时显示样本数、集合容量及剔除最强标的后的结果。

系统健康页增加数据源能力矩阵和特征产物状态：每个来源显示覆盖能力、正式/研究资格、最近成功、降级原因和条款复核时间；每个特征版本显示快照、分区、哈希、行数、构建进度和是否可重建。长任务允许管理员请求取消或重试，但界面必须说明取消在当前原子步骤完成后生效。

## 10. 响应式验收

- 桌面主页以 `1280×720` 无滚动完整显示为回归门槛；新增首页模块前必须重新测量正文高度，不能把每日简报入口推到第二屏。
- 桌面优先紧凑横向比较；移动端改为完整卡片，允许纵向滚动，但不得横向溢出或隐藏核心字段。
- 关键理由与风险不可无提示截断；详情可展开。
- 异步刷新不造成明显布局跳动。
- 真实浏览器覆盖桌面和移动视口，检查导航、确认流程、错误/降级状态和长文本。
- 实验各折对照、规则差异、数据源能力矩阵和特征构建进度在移动端必须转为完整卡片，不得仅依赖横向表格。
