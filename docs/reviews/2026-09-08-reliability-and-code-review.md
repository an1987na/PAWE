## 故障证据及与此前原因的比较

| 原因 | 实际证据 | 本次处理 |
|---|---|---|
| 多调度线程为每次任务创建新事件循环，却复用同一 asyncpg 连接池 | 9 月 1 日收盘任务与队列并发时报 `Future attached to a different loop`、`unknown protocol state 3` | 所有调度线程提交至一个长期运行的事件循环，不再逐任务关闭连接池 |
| 同步行情请求取消不彻底 | Sina 经 `to_thread` 调用，超时不能停止同步请求；日志出现执行器线程退出等待超过 300 秒 | 默认 Sina 请求放入可终止子进程，超时/取消后终止并回收 |
| 少量缺失成交额阻止完整快照冻结 | 本周 343 只分类标的中 337 只成功，6 只缺失；腾讯价格/成交量不能代替成交额 | 补抓 000937、001286、002422、300613、300633、603960；自动流程新增最多两轮针对性修复，保持完整冻结门禁 |
| 耗时准备阻塞输出队列；迟到触发被丢弃 | 队列反复达到 `max instances (1)`，任务长期 queued；08:30 任务曾迟到 4 分 38 秒被丢弃 | 周初和输出队列拆开；输出通道串行；调度迟到容忍 6 小时并合并触发 |
| 日报失败后恢复机会不足 | 仅依赖计划触发、启动及周末补做，工作日缺失可持续积累 | 每 30 分钟在正式窗口内检查遗漏日期；单日失败不阻断其他日期 |

此前“增加调度线程”和“补足分类样本/行情”的修复只解决容量和输入，不解决异步连接的生命周期；增加线程还会暴露跨循环并发问题。本次不是把原因归为 Docker 未启动，也不是仅手工重跑一次。

## 代码审查建议（未实施）

### P1：任务租约、心跳与业务完成度

位置：`apps/api/pawe_api/jobs/repository.py` 的 claim/finish 路径、`services/worker/pawe_worker/main.py`。

本次修复了连接循环和队列阻塞，但持久任务仍缺少 Worker 租约、心跳和进程终止后的自动认领恢复。定时任务也未全部先写入持久任务表，进程活着不等于业务按期完成。建议统一手动与定时的入队、领取、进度、超时与有限重试；按交易周检查预期产物数量并报告缺口。增加进程被杀、休眠恢复、数据源长时间失效的真实 PostgreSQL 集成测试。多 Worker 部署前增加数据库级批次锁，不能只依靠进程内锁。

### P1：发布冻结应由服务端统一强制

位置：`apps/api/pawe_api/decisions/repository.py::_approval_source`、`_create_approved_decision`。

后者会将同周活动 published 决策置为 superseded，没有检查它是否已经正式发布。当前同一来源再次审批被状态拦截，但若同周出现另一待审批来源/版本，仍有替换已发布名单的路径风险。建议在周级锁内统一拒绝发布后的新审批/替换；增加 rule→发布→另一来源审批及并发测试。不要依赖前端隐藏入口保护冻结规则。

### P1：人工换股缺少组合约束复核

位置：`apps/api/pawe_api/decisions/repository.py::_validate_manual_selection`。

目前验证容量不变、标的属于 eligible，未复核主领域数量、补充/跨领域容量、行业集中度和市场状态附加条件。单股合格不代表组合合格。建议审批与发布复用同一组合验证器，并保留验证规则版本和结果；这是保护已确认规则，不是修改投资规则。

### P1：AI 业务成功状态与能力描述不一致

位置：`apps/api/pawe_api/ai/service.py::weekly_selection`、`_invoke`。

周初 AI 目前只接收规则最终名单的代码、名称和决策项 ID，没有完整合格候选池及事实证据内容；保存分析后也不形成独立 AI 决策版本。“非零调分不超过 2 只”并不等于“最多替换 2 个名额”。此外 `_invoke` 在候选/证据白名单业务校验前提交 succeeded，随后业务校验失败会留下成功调用记录。建议区分传输成功、结构成功、业务接受；输入冻结证据包，生成可审计 AI 版，按实际名单差集校验换位数量。错误归因/规则提案保留人工确认与实验门禁，不自动升级正式规则。

### P2：贪心组合可能错误报告候选不足

位置：`apps/api/pawe_api/rules/portfolio.py::_select_size`。

隔离复现：按分数依次输入 A 行业补充 2 只、A 行业主领域 2 只、B 行业主领域 1 只、C 行业补充 2 只。全池返回 3 只；仅移除最前两只后返回 5 只。可行 5 只组合原本就存在，问题是贪心选择不回退。建议最大容量仅 5 时采用有剪枝的确定性搜索，保留原排序作为同优先级选择标准，并覆盖类别交叠/状态限制的反例。

### P2：数据覆盖和特征完成度需要显式展示

位置：`scripts/materialize_technical_snapshot.py`、`scripts/materialize_v9_inputs.py`、`apps/api/pawe_api/features/weekly.py`。

343/343 是分类研究池完整，并不等于全 A 股研究特征齐全。当前物化主动采用 degraded 市场状态输入；直接催化、财务不恶化等字段保守设为 False、证据数为 0。建议展示全市场→有效分类→完整行情→合格候选的每级分母；优先补齐可追溯财务/公告证据与连续市场状态输入，再加强 AI，避免“任务成功”被误解为所有研究模块完备。

### P2：日线复盘的日内路径不确定性

位置：`apps/api/pawe_api/evaluation/weekly.py::evaluate_weekly_path`。

峰谷回撤每根日线先更新 high 再使用 low，隐含当天高点先于低点。日线无法证明这一先后顺序。建议将该值明确标为保守估计/界限，或使用可靠更细粒度数据；不要把日线估计当成真实可执行路径。OHLC 和阈值同时补充 NaN/Infinity 有限值检查。

### P2：个人密钥、登录保护和可观测性

位置：`apps/api/pawe_api/ai/credentials.py::AICredentialCipher`、`apps/api/pawe_api/auth/repository.py::login`、`apps/api/pawe_api/main.py::health`。

非生产环境密钥加密默认从数据库 URL 推导；使用公开默认连接配置时不能把它视为独立的密钥保护，变更连接地址也可能导致旧凭据不可解密。建议生成独立持久随机密钥并设计轮换迁移（执行前另行确认）。登录增加失败限流；health 当前主要返回配置，应另有数据库 readiness、Worker 心跳、积压任务年龄和产物缺口。不可仅凭 HTTP 200 判定业务正常。

### P2：依赖可复现、模块拆分和验收

位置：`pyproject.toml`、`services/worker/Dockerfile`、`apps/web/Dockerfile`、`apps/web/src/App.tsx`。

Python 使用宽范围依赖，Web 镜像安装时不冻结锁文件；相同代码重新构建可能得到不同依赖。本次 Worker 重建也重新解析了依赖，因此建议优先固定可重复构建的锁定清单和基础镜像。逐步按领域拆分 API 路由、Worker 编排和大页面组件；增加真实数据库事务/迁移、审批发布、历史弹框和恢复异常的端到端验收，现有 Web 测试主要覆盖日期/决策辅助函数。

建议顺序：任务可靠性与冻结约束 → 人工组合校验 → 数据证据与 AI 审计闭环 → 组合搜索和评估精度 → 模块拆分。超出本次修复的变更另行确认，不静默改写正式规则。
