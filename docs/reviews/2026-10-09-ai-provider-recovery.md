# 2026-10-09 AI 提供商修复与原生环境验证

## 已确认的代码问题与修复

- 原提供商直接使用普通 Pydantic JSON Schema，严格模式未处理嵌套对象 `additionalProperties=false` 与带默认值字段的 `required`，四类能力共用这一缺陷。改用 OpenAI SDK 严格输出解析，并以真实 SDK/HTTP Mock 验证发送契约；这属于可确认的接口缺陷，不代表已经读取小主机全部失败日志。
- 输入此前使用 Python 字典字符串，改为 JSON。原输出预算和超时较小，默认改为 4000 token/45 秒，总截止包含重试；拒绝、截断、空输出不冒充成功。
- 原提供商失败一律隐藏原因，失败审计误标为 Mock。改为安全错误分类，保留真实提供商及已发生用量；业务候选/证据/容量校验前移，避免先写成功后拒绝。
- 工作台“已连接”原本只检查是否保存凭据，新增真实连接测试并区分配置与验证。任务失败后仍刷新审计；成功分析可查看结构化结果。历史归因原来吞掉异常，改为弹框内错误提示及防重复点击。
- 移动端导航隐藏文字后无可访问名称，补齐按钮名称。

正式候选、未来数据限制、审批发布、已确认归因门禁与实验激活状态均未放宽，无数据库结构迁移。

## 环境与旧资源清理

按明确授权删除原 Mac PAWE 的 4 个容器、1 个 PostgreSQL 卷、1 个网络、11 个 PAWE 项目镜像及本次旧库冷备份；未全局清理 Docker，未删除共享基础镜像或其他项目。旧本地数据不可由本次冷备份恢复；小主机数据和备份未操作。

独立原生 Python 3.12 / Node / PostgreSQL 17 环境初始化了开发库和测试库，执行现有全部 20 个迁移。使用 `.local/native.env` 的随机凭据、独立端口，不读取旧 `.env`，不启动 Worker，不连接正式库。隔离测试数据均为虚构，并通过外层事务回滚。

## 验证与真实调用边界

- 提供商测试通过真实 SDK 和 HTTP Mock 覆盖四个严格输出契约、输入序列化、拒绝/截断/空结果、常见 API 错误和敏感响应不泄露。
- 真实 PostgreSQL 集成覆盖四类任务、工作台按周及历史按复盘 ID 的归因、确认前拒绝规则迭代、失败审计、非法候选/证据/三席位调整拒绝及用量保留，确定性决策未修改。
- 认证/CSRF、原生环境隔离、针对性静态检查、前端单元测试和生产构建完成。真实 Chromium 的 1440 与 390 像素视口检查登录回车、连接状态、结果/失败审计、历史归因错误和无横向溢出；业务响应使用明确的虚构浏览器夹具，不代表真实模型已生成研究结论。
- 最终对应检查：提供商/连接/隔离原生库测试 25 项、既有 AI 能力测试 10 项通过；此前相关认证及 DSL 检查通过，前端 19 项单元测试通过。Ruff 代码检查与变更文件格式检查通过，Mypy 6 个源文件通过，最终 Web 类型检查及生产构建通过。扩大到未改动的 AI 目录做格式预检时发现既有 `credentials.py` 格式差异，未改动该文件；变更文件无此问题。未运行全库测试或宣称 CI 通过。
- 获授权读取用户指定密钥后，仅发起最小 `gpt-6.1-sol` 连接验证（提供商允许一次自动重试）。OpenAI 官方 API 返回 HTTP 429，安全分类为 `OPENAI_RATE_LIMITED`，不是成功。未继续四类真实付费调用，不从错误响应推断账户余额或模型权限，也未保存密钥到仓库、报告或聊天。
