# 产品范围与验收

> 状态：MVP 目标需求

## 1. 产品定义

PAWE（Pick A Weekly）是个人使用的 A 股 AI 周度研究系统。它扫描全 A 股，以规则形成候选，以 AI进行有证据的有限调整，经人工确认后以 5 只为目标且最多发布 5 只具有约 10% 周内最高涨幅研究情景的观察标的，在每个交易日收盘后生成主要标的简报，并在周终验证规则、AI和人工各自的真实贡献。硬约束和组合约束后不足 5 只时按实际合格数量发布；没有合格标的时停止发布。

产品不是自动交易系统，不保证收益，不提供券商下单能力。

## 2. 目标与非目标

### 目标

1. 稳定、可复现地生成每周目标且最多 5 只观察标的；每只都必须具备约 10% 周内最高涨幅的研究情景、证据和失效条件，不足时按实际合格数量发布并说明原因。
2. 证明 AI 相对纯规则是否产生可量化增益。
3. 让每次结果进入错误归因和影子实验，形成受控迭代闭环。
4. 默认只展示结果与重要描述，证据和审计按需查看。
5. 本机可用，并保持向私有云迁移的同构能力。

### MVP 非目标

- 自动下单、券商连接、实盘仓位管理。
- 收益保证、目标价承诺、盘中追涨信号。
- 用户间协同编辑、公开社区、付费数据源；MVP仅提供管理员和只读普通用户。
- 名人投资风格 Agent、无约束自主交易 Agent。
- 模型自主修改正式规则或绕过人工审批。
- 复杂研报 RAG、MCP、PDF 专业报告；这些可在后续阶段评估。

## 3. 用户与核心流程

MVP 有两个角色：管理员拥有完整使用、审批、发布和用户管理权限；普通用户可查看研究内容，并且和管理员一样只能增删本人的最多 5 只自选关注，除此之外仍为只读。所有业务页面都要求登录，管理员通过本地幂等初始化命令创建，并可新增或停用普通用户。

### 周初流程

1. 系统冻结上个交易日收盘前的数据快照。
2. V9.0 扫描全 A 股并形成规则候选与目标且最多 5 只的规则基准；不足时保留实际合格数量。
3. AI基于统一事实底稿分析候选，执行验证并有限调整。
4. 系统展示规则版与 AI版差异；用户确认、替换或驳回。
5. 发布最多 5 只的正式集合；不足时按实际合格数量发布，零只时停止发布并展示候选稀缺，发布后当周名单不可被盘中任务自动改写。

### 每日流程

1. 每个交易日收盘后，以当周正式发布的实际标的集合为唯一范围冻结日度数据。
2. 计算当日、周内、目标进度、成交活跃度、回撤和数据质量状态。
3. 汇总截至当日公开的公告、新闻和风险证据；AI仅能生成有引用的简报，不得调整名单。
4. AI不可用时降级为确定性行情简报；关键行情缺失时标记失败或降级，不沿用旧结论冒充当日简报。

### 周终流程

1. 以当周首个交易日开盘价为统一研究基准；周一休市时顺延至首个交易日。
2. 分别评价规则基准、AI调整和人工发布三套结果。
3. 计算触达、留存、回撤、超额与可执行指标。
4. 对错误分类，生成优化提案；提案不得直接进入正式策略。

### 实验流程

1. 新规则、提示词、模型或权重创建实验版本。
2. 先进行无未来数据泄漏的历史 walk-forward 回放。
3. 再进行实时影子运行，不影响正式发布。
4. 达到门槛后由用户批准升级；否则保留现行版本。

## 4. MVP 功能

| 模块 | 必须能力 |
|---|---|
| 周度驾驶舱 | 当周实际发布标的、市场状态、置信度、核心理由、主要风险、最新简报；桌面单屏优先 |
| 历史数据 | 内容按交易周收敛，点击周记录后在弹框查看完整名单、日报、复盘和逐标的详情 |
| 每日简报 | 当周实际标的与个人自选在指定交易日的日涨跌、相对近5日量能、当日消息证据和数据状态；不承担周行情汇总 |
| 我的自选 | 每位用户独立关注最多 5 只沪深 A 股；从生效交易日起进入本人的日报和周终复盘，不影响公共规则与名单 |
| 市场雷达 | 指数、市场广度、主领域热度、全市场强势领域、数据状态 |
| 候选中心 | 规则候选、规则前 5、AI前 5、备选、科创参考、跨领域探索及落选原因 |
| AI决策确认 | 规则/AI差异、证据、风险、人工确认与修改原因 |
| 个股摘要 | 行情特征、领域强度、公告/资金/新闻摘要、历史入选记录 |
| 周终复盘 | 三版本对照、传统指标、可执行指标、错误归因、失败周反查 |
| 实验记录 | 版本、参数、回放结果、影子结果和批准状态 |
| 系统健康 | 数据源、任务、AI提供商、缓存和降级状态 |
| 设置 | 科创板开关、AI权限、人工/自动发布模式、数据和模型配置 |
| 用户管理 | 管理员初始化、新增/停用普通用户、登录会话和认证审计；普通用户只读 |

## 5. 关键产品约束

- 最终以 5 只为目标和上限；硬约束或组合约束后可发布 1～5 只，少于 5 只时必须标记 `CANDIDATE_SHORTAGE` 和低置信度，不以不合格标的凑数；零只时标记 `NO_ELIGIBLE_CANDIDATE` 并停止发布。
- 约 10% 是逐标的周内最高涨幅研究情景和核心复盘指标，不是收益保证。任何正式入选项都必须记录目标情景、触达概率、核心证据、主要风险和失效条件。
- 主领域至少 3 只；补充领域与跨领域席位合计最多 2 只，跨领域最多 1 只。
- AI最多改变规则基准前 5 中的 2 个名额，调整分限制为 -10～+10。
- 初期只能人工确认发布。自动化条件见评估规范。
- 默认页面不显示冗长分析或模型内部推理；工具调用、证据、结构化判断与版本记录可审计。

## 6. MVP 验收

MVP 只有同时满足以下条件才算完成：

1. 任一完整交易周可从冻结快照生成规则、AI、人工三版本结果。
2. 最终名单满足 V9.0 全部硬约束，且每个入选/落选结果可解释。
3. 周终指标计算经过固定样例测试，与公式一致。
4. AI不可用时可明确降级，不影响规则基线的可复现性。
5. 任一正式结果可由数据快照、规则、模型、提示词和人工记录重放。
6. 桌面与移动端完成真实浏览器验收，首页保持低信息密度。
7. 数据源异常、任务失败、低置信度和候选稀缺都有明确状态。
8. 本机 Docker 环境可运行；尚未经过云端安全与运维验收时不得称为生产就绪。
9. 任一交易日可为当周实际发布标的生成唯一、可重放的收盘后简报；简报不得改写正式名单，AI降级时仍能输出确定性行情部分。
