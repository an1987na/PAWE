# 数据源契约与核心数据字典

> 状态：MVP 数据设计。所有供应商均通过适配器接入，业务逻辑只读取统一字段。

## 1. 数据原则

- 只使用免费公开接口，不把任何单一网站视为稳定 SLA 数据服务。
- 每条记录保存来源、交易日、获取时间、原始标识、复权方式和质量状态。
- 数据源异常不得静默变为0；应返回缺失、降级或冲突状态。
- 周初快照冻结后不可被后续修订覆盖；修订数据另存版本。
- 历史回放使用当时可见的数据与分类，禁止未来信息泄漏。

## 2. 数据源路由

| 数据 | 首选 | 备用/补充 | MVP要求 |
|---|---|---|---|
| 股票主数据、交易日历 | 交易所公开信息、东方财富 | AkShare | 每日更新，保留历史状态 |
| 实时行情、主要指数 | 腾讯行情 HTTPS | 东方财富 push2delay | 无 Key；标记实时/延迟 |
| 前复权日线 | 腾讯 K线 HTTPS | 东方财富、新浪（AKShare） | 双源抽样校验；新浪严格限速 |
| 正式行业与领域 | 中国上市公司协会、中证/国证指数 | 巨潮年报人工批准证据 | 分类与成员关系带公开日和有效期 |
| 商业概念候选发现 | 东方财富 | AkShare | 仅辅助发现，不授予正式领域 |
| 市场广度、涨跌停、成交榜 | 东方财富 | AkShare | 失败时市场状态不可伪造 |
| 公告 | 沪深北交易所公开信息 | 东方财富聚合 | 保存发布日期和报告期 |
| 财务关键指标 | 东方财富数据中心 | AkShare/同花顺公开数据 | 报告期与披露日分离 |
| 研报 | 东方财富公开研报 | 无 | 仅作证据，不视为事实真值 |
| 资金、两融、龙虎榜、解禁 | 东方财富数据中心 | AkShare | 标记缺失与更新时间 |
| 新闻与产业资讯 | 公开 RSS/Atom | 公告与公开网页摘要 | 保留链接、发布时间和抓取时间 |

云端部署前必须重新验证公开接口的访问条件、节流要求与使用条款。

当前交易日历实现以沪深交易所年度休市公告作为双来源：解析后的自然周开闭市日期必须完全一致才标记 `verified`；来源冲突标记 `conflicted`，仅备用来源标记 `degraded` 并停止周度准备。2026 年来源为[上交所年度休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/)与[深交所年度休市通知](https://investor.szse.cn/disclosure/notice/general/t20251222_618087.html)。日线只能用于事后确认，不能推断未来交易日。

当前股票主数据以沪深交易所官方列表作为正式运行的完整性硬要求，北交所为可选市场：系统仍尝试读取北交所，失败时记录 `optional_market_unavailable` 降级原因，但不阻止沪深原子批次入库。待北交所官方接口或巨潮资讯备用适配器稳定后再恢复三市硬要求。东方财富保留为显式补充路线，不会静默替代官方市场。交易所代码规则用于校验交易所与板块；沪深任一拒绝行、分页缺口或来源交叉冲突都会整批停止，不允许猜测补齐或先写单一市场。北交所同时识别当前 `920` 代码和历史 `4/8` 开头代码，深交所创业板同时识别 `300/301/302` 代码段。来源行业按 `provider_industry` 保存历史有效期，不直接推断 PAWE 领域归属。

正式领域分类采用三层版本：`capco_industry` 保存中上协半年行业底座，`official_theme` 保存中证/国证官方主题样本，`pawe_primary` 保存解析后的唯一 `domain + sector_code`。中上协两位行业大类只有在整个大类明确属于同一方向时才可直接映射；当前仅将煤炭、油气、石油加工与电力生产等明确大类映射为能源，不把宽泛的电子设备、专用设备、软件行业猜测为半导体、机器人、医疗器械或 AI。中证当前接入 `931071` 人工智能、`H30590` 机器人、`H30184` 半导体、`931152` 创新药、`H30217` 医疗器械的官方样本列表。动态样本文件从实际抓取日开始可用于决策，不能倒灌到更早回放；同级主题冲突不生成主领域。

2026-08-09 实际验收：中上协 2025 年下半年 PDF 解析 `5463` 条，其中 `5155` 条与当前沪深主表精确匹配；未匹配项主要为暂不纳入的北交所、B 股及退市代码。五个中证主题文件的数据日期均为 2026-08-07，分别解析 AI `50`、机器人 `64`、半导体 `87`、创新药 `50`、医疗器械 `99` 条；剔除 2 个北交所未知代码并解析唯一主领域后，沪深共 `465` 只 ready、`14` 只 conflicted、`4727` 只 missing。missing/conflicted 不得进入 V9 正式候选池。

2026-08-09 实际验收：上交所当前股票页面使用 `sseQuery/commonQuery.do`，旧 `getStockListData2.do` 已用于首次发行待上市列表，先前 `405/612` 差异属于适配器接口用途漂移。修正后上交所 `2311/2311`、深交所 `2895/2895` 全部通过，沪深共 `5206` 只已原子入库；北交所列表接口仍返回 `403`，批次明确标记为降级。沪深两只代表股票已完成双源日线抽样，均为 `verified`，且可使用带成交额的东方财富版本计算技术特征。

日线填充使用窗口绑定的本地断点文件，逐只股票提交数据库事务后原子推进代码游标；失败代码单独留在重试队列，重跑不会覆盖历史版本。正式周度批次只处理在当周评价入口日有效、在决策截止日已经公开且在快照锁定前已经抓取的唯一 `pawe_primary` 分类；缺失和同级冲突成员显式排除，科创板默认在快照构造前排除。`decision_cutoff` 固定为上个完整交易日 15:00，`fetched_by` 可放宽到当周首个交易日发布前；数据交易日仍不得晚于 `decision_cutoff`，从而允许周末完成抓取但不改变信息截止日。每只股票的快照记录保存最近61个交易日的来源原始值、分类时间边界、行业5日上涨占比、行业成交活跃度中位数、同池波动率分位、抓取时间和派生指标；非科创正式范围内任何股票失败都会阻止该范围快照持久化。

15:30 日报不能假设前复权日线接口已经刷新。若腾讯 `qfqday` 尚未包含当日，但同一响应的实时行情时间已过 15:00 且沪深市场状态明确为已收盘，适配器可用当日开、高、低、收、成交量和成交额补成同源收盘记录，并标记 `same_day_close_quote_fallback`。该记录仅用于收盘后日报，质量最高为 `single_source`；不得用于开盘前周初选择。东方财富失败时自动日报采用 5 秒、零重试的快速降级，不等待可能拖住进程的新浪线程；历史批量采集仍保留新浪限速备源。

2026-08-09 最新正式范围预览为 463 只活跃沪深股票；其余 4539 只因没有唯一有效主领域而不进入当前周度候选基础范围。东方财富间歇性空响应时启用新浪/AKShare 备源，单主机请求间隔不少于 2 秒。新浪成交量原始单位为股，入库前除以 100 归一为手。若腾讯与新浪日期、成交量和前复权价格均一致则为 `verified`；若日期和成交量一致但前复权因子造成价格差异，仅使用腾讯价格和新浪成交额，并标记 `single_source`、`amount_fallback:sina` 与 `price_verification_unavailable:qfq_factor_conflict`；成交量、日期或复权类型冲突仍为 `conflicted`。

真实验收中，深市 `000027` 达到 `verified`；沪市 `600011` 因复权因子差异按确认口径生成 `single_source` 特征。正式断点已推进 35 只、游标到 `000966`，失败队列为 0；对应前 35 只分类行情预览全部成功，其中 `verified` 32 只、`single_source` 3 只。另有 4 只沪市人工探测样本已经保存，因此数据库当前共有 39 只正式标的具备腾讯与新浪来源记录。

## 3. 适配器契约

所有适配器返回统一信封：

```json
{
  "source": "tencent",
  "as_of": "2026-07-31T15:00:00+08:00",
  "fetched_at": "2026-08-02T09:00:00+08:00",
  "quality": "verified",
  "is_delayed": false,
  "data": [],
  "warnings": []
}
```

质量枚举：

- `verified`：通过结构和交叉校验。
- `single_source`：只有一个来源但结构正常。
- `degraded`：使用备用源或延迟线路。
- `conflicted`：多源关键值超出容差。
- `missing`：无可用数据。

`conflicted` 与关键字段 `missing` 的股票不得进入主池。

### 数据源能力矩阵

适配器注册时必须声明可机器读取的能力，不再由业务代码根据供应商名称猜测。最小字段包括：

| 字段 | 说明 |
|---|---|
| `source_id/adapter_version` | 来源与适配器版本 |
| `dataset/capabilities` | 可提供的数据集、复权、历史深度、分页与增量能力 |
| `market_coverage` | 覆盖交易所、板块、代码范围和日期范围 |
| `time_semantics` | `as_of/published_at/fetched_at` 的可用性与精度 |
| `auth_mode/terms_reviewed_at` | 认证方式及最近一次条款核对日期，不保存密钥 |
| `rate_limit/timeout/retry_policy` | 节流、超时和有限重试策略 |
| `quality/formal_eligibility` | 当前质量及是否允许进入正式决策链 |
| `fallback_priority` | 同一数据集的主备次序与允许降级范围 |
| `last_success/last_failure` | 最近成功、失败和失败原因 |

能力矩阵由健康检查和任务门禁共同读取。来源“在线”不等于能力“可用于正式决策”；缺少时点语义、复权口径或完整覆盖时只能进入研究/展示链路。

字段映射允许使用版本化声明配置，但只支持重命名、类型转换、单位换算、枚举映射、空值规则和白名单派生函数。不得在映射配置中执行任意 Python、SQL 或网络调用。新映射先写入隔离暂存区，通过固定样例、行数守恒、字段范围、时点和多源抽样校验后，才可由人工批准成为适配器正式版本。

## 4. 截止时间与复权

- 时区统一为 `Asia/Shanghai`，数据库时间使用带时区时间戳。
- 周初选择快照的 `as_of` 不晚于最近一个完整交易日15:00。
- 公告和新闻以真实公开时间判断是否可用；只有日期无时间且发布日期等于截止日时，默认次日可用，避免日内泄漏。
- 日线默认前复权 `qfq`；原始不复权价格保留用于审计。
- 前复权历史值可能随公司行为改变；`daily_bars` 按内容保留多个抓取版本，特征构造只选择 `fetched_at <= snapshot_cutoff` 的最新可见版本，禁止用后续复权结果覆盖历史快照。
- 周终首个交易日开盘基准与周内 OHLC 必须使用同一复权序列。

## 5. 缓存、节流与降级

- 行情和静态资料分开缓存；市场总览默认5分钟，日线在交易日收盘后冻结。
- 东方财富等公开接口统一限流，默认同一主机串行间隔不少于1秒并加入轻微抖动。
- 请求设置连接/读取超时、有限重试和熔断；不得无限重试阻塞周初任务。
- 代理模式、直连模式及切换结果写入健康记录；国内数据源默认直连优先。
- 降级数据可用于展示，但影响硬约束、复权或市场状态时必须阻止发布或要求人工确认。

冻结快照同时保存逐条原始记录：`record_key`、`source`、`as_of`、`fetched_at`、`published_at`、`adjustment`、规范化 `payload` 与 `content_hash`。特征和市场状态输入必须绑定同一 `snapshot_id` 及各自 Schema 版本；只有摘要哈希而没有原始记录的快照不视为完整可重放快照。

### 特征产物与加速层

PostgreSQL 是快照、正式特征清单和业务状态的唯一权威来源。Parquet/DuckDB 只作为可重建的历史分析与批量特征加速层，不得反向覆盖 PostgreSQL 正式记录。

每个特征分区必须带 `feature_manifest`：`snapshot_id`、分区键、`schema_version`、`feature_version`、代码版本、`decision_cutoff`、源记录哈希集合、行数、内容哈希、质量状态、创建时间和构建任务。构建流程为“临时分区 → 完整性与哈希校验 → 原子发布”；失败或取消只删除未发布临时产物，不留下可读取的半成品。

重建必须绑定明确的日期/股票范围和内存预算，按分区流式执行，不允许默认把全市场全历史载入内存。相同快照、特征版本和代码版本应生成相同内容哈希；不一致时标记冲突并阻止用于正式选择。

### 每日简报

| 字段 | 说明 |
|---|---|
| `brief_date` | 简报对应交易日 |
| `decision_set_id` | 当周正式发布决策版本，决定简报覆盖范围 |
| `as_of/fetched_at` | 数据截止与抓取时间 |
| `daily_return` | 当日收盘相对前收盘涨跌幅 |
| `volume_activity` | 当日成交量相对前 5 日均量 |
| `evidence_ids` | 截至当日新增或仍有效的证据引用 |

日报的正式展示与摘要只陈述指定交易日的日内行情，不展示或推断周内进度、周内高点、目标距离或周度风险状态。数据库中已有的 `week_*`、`distance_to_target` 和 `risk_status` 字段暂作为历史兼容与周终计算的内部数据保留，不属于日报对外事实契约；后续数据库迁移可在确认历史兼容方案后移除。

## 7. 数据健康验收

- 两只不同交易所股票可完成主备日线抽样校验。
- 股票主数据必须满足分页总数、接受数和拒绝数守恒；任一拒绝行都会阻止整批入库。
- 当前阶段沪、深两市必须全部成功；北交所失败必须显式降级，不能伪装为三市完整。上交所科创板主数据必须与其官方 `kshare` 列表代码集合完全一致。
- 交易日历能正确处理长假和非完整周。
- 公告披露时点测试能阻止未来信息进入快照。
- 复权样例在除权日前后连续且周终公式一致。
- 主源失败时出现明确降级状态；关键数据缺失时阻止自动发布。
- 交易日历双源一致时标记 `verified`；仅备用源可用时即使能够判定一周有至少 3 个交易日，也必须停止周度准备并转人工排查。
- 数据源能力矩阵能区分“在线”“可研究”和“可用于正式决策”，能力或条款状态过期时不得静默放行。
- 特征产物必须通过清单哈希、行数、时点与原子发布测试；中断构建后正式分区保持不变且可以从检查点重试。
